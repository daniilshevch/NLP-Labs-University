# Лабораторна робота 5 — Генерація тексту

Практична робота з використанням авторегресійної мовної моделі GPT-2 для генерації тексту.

## Коротко

- Цикл генерації написано з нуля поверх `logits` моделі, без `model.generate()`.
- Реалізовано 5 стратегій декодування з однаковим інтерфейсом `sample_fn`: greedy, sampling, temperature, top-k і top-p (nucleus).
- Поведінку кожної стратегії показано на реальних генераціях: від зациклення greedy до «шуму» при високій температурі.
- Zero-shot експеримент показав, що GPT-2 не оцінює тональність: і негативному, і позитивному відгуку модель «ставить» 5 із 5.

## Мета

Розібрати принцип генерації тексту мовною моделлю: отримати розподіл імовірностей наступного токена, реалізувати різні стратегії декодування та генерувати текст із заданого prompt.

## Виконані етапи

- Завантажено попередньо навчену модель `GPT-2` через Hugging Face Transformers.
- Завантажено відповідний GPT-2 tokenizer.
- Досліджено токенізацію:
  - перетворення тексту на числові token IDs;
  - перетворення ID назад у токени;
  - розбиття рідкісних слів на підслова.
- Проаналізовано один крок роботи causal language model:
  - подано початковий `bos_token`;
  - отримано logits для словника;
  - перетворено logits на ймовірності через softmax;
  - розглянуто log-probabilities та числову стабільність.
- Реалізовано greedy decoding — вибір токена з найбільшою ймовірністю.
- Створено цикл генерації до появи `eos_token` або до досягнення `max_len`.
- Реалізовано BPE-декодування та перетворення послідовності токенів назад у звичайний текст.
- Узагальнено генератор через параметр `sample_fn`, щоб змінювати стратегію вибору наступного токена.
- Реалізовано та перевірено:
  - greedy choice;
  - простий випадковий sampling пропорційно ймовірностям;
  - sampling з temperature;
  - top-k sampling;
  - nucleus sampling (top-p).
- Додано генерацію тексту від заданого prompt, а не лише з початку речення.
- Проведено простий zero-shot експеримент: GPT-2 використано для продовження відгуків із позитивною та негативною тональністю.
- Порівняно власну реалізацію з готовим методом `model.generate()` у Transformers.

## Результати та спостереження

### Порівняння стратегій декодування

| Стратегія | Поведінка |
|---|---|
| Greedy | Детермінована, але швидко зациклюється: *«I was so excited to see the new version of the game, I was so excited to see…»* |
| Sampling (T = 1.0) | Різноманітний, але часто незв'язний текст, з фрагментами коду та випадковими іменами |
| Temperature | `T = 0.1` повторює greedy, `T = 0.5–0.8` дає зв'язні й різні речення, з `T ≥ 1.25` текст розпадається на набір слів, а `T ≥ 3` дає навіть биті байти BPE |
| Top-k (k = 15) | Відсікає «хвіст» маловірогідних токенів, і текст стає граматично зв'язним, у стилі новин |
| Top-p (nucleus) | `p = 0` еквівалентне greedy, `p = 0.1–0.5` дає зв'язні новинні речення, а з більшим `p` різноманітність зростає разом із ризиком повторів і нісенітниць. Розмір множини кандидатів адаптується до впевненості моделі |

### Zero-shot класифікація через prompt

| Prompt | Продовження GPT-2 (greedy) |
|---|---|
| *This film is awful! Actor play is terrible. The plot is dull. On the scale of 1 to 5 I would rate it as a* | **5** |
| *This film is amazing! The time flies by when you watch it. Definitely recommend! On the scale of 1 to 5, I would rate it as a* | **5** |

Базова GPT-2 (124M) продовжує текст за поверхневою статистикою: після *«rate it as a»* найчастіше йде *«5»*, незалежно від змісту. Без instruction tuning або донавчання вона не виконує задачу класифікації. Саме тому в наступних роботах для цієї задачі використано fine-tuning BERT ([Lab7](../Lab7/README.md)).
