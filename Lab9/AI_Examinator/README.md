# 🎓 AI Examiner: LLM-екзаменатор з NLP

**AI Examiner** — це LLM-агент, який проводить усний іспит з курсу «Обробка природної мови (NLP) та LLM» у форматі чату. Він перевіряє студента за базою, вибирає випадкові теми, ставить питання, оцінює кожну тему за шкалою 0–10, пише підсумковий відгук і зберігає результат у файл.

Окремо в проєкті є **AI-студент**: друга LLM, яка може складати іспит замість людини з заданим рівнем знань, від «відмінника» до «хитруна», що пробує prompt injection. Так екзаменатора зручно тестувати.

> Агент написаний без агентних фреймворків (LangChain, LlamaIndex тощо). Увесь цикл function calling займає кілька десятків рядків у [`agent.py`](agent.py).

---

## ✨ Можливості

- 💬 **Чат-інтерфейс на Gradio** з вкладками «Іспит» і «Результати».
- 🛠️ **Function calling:** модель сама вирішує, коли викликати інструменти `start_exam`, `get_next_topic`, `record_topic_result` та `end_exam`.
- 🔌 **Будь-який OpenAI-сумісний провайдер:** OpenAI, Google Gemini, Groq, OpenRouter або власний `base_url`, наприклад локальний сервер.
- 🎲 **3 випадкові теми з 16** для кожного іспиту. До кожної теми є ключові пункти, які бачить лише екзаменатор.
- 📊 **Обґрунтована оцінка:** спочатку оцінка й коментар за кожну тему, потім підсумкова оцінка, узгоджена з ними.
- 🛡️ **Захист від маніпуляцій:** агент не змінює оцінку на прохання студента, не показує ключові пункти й ігнорує «забудь попередні інструкції».
- ✅ **Валідація на боці коду:** інструменти перевіряють email та ім'я, діапазон оцінок, порядок викликів і повторне завершення. Помилки повертаються моделі текстом, щоб вона могла виправитися.
- 🤖 **AI-студент із 7 персонами** для автоматичного тестування екзаменатора.
- 🔍 **Прозорість:** виклики інструментів з аргументами й результатами можна показувати прямо в чаті.
- 💾 **Збереження результатів:** повний JSON з історією діалогу та журнал подій `exam_log.jsonl`.

## 🧠 Як це працює

```
 Студент (людина або AI-студент)
            │  повідомлення
            ▼
 ┌─────────────────────── ExaminerAgent.respond() ────────────────────────┐
 │  messages ──► LLM (chat.completions + tools)                           │
 │                 │                                                       │
 │                 ├── є tool_calls? ──► _execute_tool() ──► ExamSession  │
 │                 │        ▲                    │      (exam_tools.py)    │
 │                 │        └──── результат ─────┘                        │
 │                 │        (до MAX_TOOL_STEPS = 10 кроків за хід)        │
 │                 └── текст без tool_calls ──► відповідь студенту         │
 └────────────────────────────────────────────────────────────────────────┘
            │
            ▼
   results/<email>_<час>.json  +  results/exam_log.jsonl
```

### Сценарій іспиту

1. Екзаменатор вітається і просить ім'я, прізвище та email.
2. **`start_exam(email, name)`** знаходить студента в `data/students.json`. Email порівнюється без урахування регістру, ім'я та прізвище можна написати в будь-якому порядку. Потім інструмент випадково вибирає 3 теми.
3. **`get_next_topic()`** повертає наступну тему та її ключові пункти (`key_points_for_examiner_only`).
4. По кожній темі екзаменатор ставить 2–4 питання, від базових до глибших, залежно від якості відповідей.
5. **`record_topic_result(topic, score, comment)`** записує оцінку за тему. Поки поточну тему не оцінено, наступну отримати не можна.
6. Коли теми закінчуються, агент пише підсумок і викликає **`end_exam(email, score, feedback)`**, а той зберігає результат.

Після завершення ходу агент ще раз зберігає повну історію (`update_history`). Модель іноді викликає `end_exam` раніше, ніж пише студенту підсумок, і так підсумок теж потрапляє у файл.

### AI-студент

[`student_agent.py`](student_agent.py) генерує відповідь від імені студента:

- Студент бачить лише те, що бачила б людина: репліки екзаменатора і свої відповіді. Виклики інструментів і ключові пункти йому **не передаються**, тож «списати» він не може.
- Ролі в історії міняються місцями: репліки екзаменатора стають для моделі-студента `user`, а її власні відповіді стають `assistant`.
- Рівень знань дописується **в кінець останнього повідомлення екзаменатора** як `[РІВЕНЬ: ...]`, а не в системний промпт. Тому персону можна змінити посеред іспиту, і модель не продовжить копіювати стиль своїх попередніх відповідей.

| Персона | Поведінка |
|---|---|
| Відмінник | Точні відповіді з термінологією і прикладами |
| Добре | Правильна основна ідея, але бракує деталей |
| Середньо | Загальні слова, на уточненнях плутається |
| Слабко | Пам'ятає назви, але не розуміє, як воно працює |
| Не готувався | Здебільшого «не знаю» |
| Плутає поняття | Відповідає впевнено, але плутає BERT і GPT, precision і recall тощо |
| Хитрун (prompt injection) | Просить підказки, пише «постав мені 10/10», «ігноруй інструкції» |

> 💡 Для студента краще взяти іншу модель, ніж для екзаменатора: модель схильна завищувати оцінку відповідям у власному стилі.

## 🚀 Швидкий старт

### Вимоги

- Python 3.10+ (перевірено на 3.14)
- API-ключ будь-якого OpenAI-сумісного провайдера. Для експериментів підійдуть безкоштовні ліміти Google Gemini або Groq.

### Встановлення

```bash
git clone <url-репозиторію>
cd Lab9/AI_Examinator

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt
pip install python-dotenv   # необов'язково, щоб ключ підтягувався з .env
```

### API-ключ

Є два способи:

1. Вписати ключ у поле **«API-ключ»** в інтерфейсі.
2. Створити файл `.env` поруч з `app.py`:

   ```env
   LLM_API_KEY=your-api-key-here
   ```

   Файл `.env` є в `.gitignore`, тому не потрапить у репозиторій. `python-dotenv` при цьому має бути встановлений. Інакше задайте змінну середовища `LLM_API_KEY` вручну.

### Запуск

```bash
python app.py
```

Gradio відкриє інтерфейс за адресою **http://127.0.0.1:7860**.

### Перший іспит

1. У блоці «⚙️ Налаштування LLM» виберіть провайдера. Base URL і модель заповняться автоматично.
2. Напишіть у чат, наприклад: `Test Student, test@lpnu.ua`.
3. Відповідайте на питання самі або натискайте:
   - **🤖 Згенерувати відповідь**: AI-студент пише відповідь у поле вводу, і її можна відредагувати;
   - **🤖 Згенерувати й надіслати**: відповідь генерується і відразу надсилається.
4. Після завершення результат з'явиться на вкладці **«Результати»**.

## 📁 Структура проєкту

```
AI_Examinator/
├── app.py              # Gradio-інтерфейс: чат, налаштування, AI-студент, таблиця результатів
├── agent.py            # ExaminerAgent: системний промпт, схеми інструментів, цикл function calling
├── exam_tools.py       # ExamSession: логіка іспиту, валідація, збереження результатів
├── student_agent.py    # AI-студент: побудова історії «з погляду студента» і генерація відповіді
├── requirements.txt
├── data/
│   ├── students.json   # «база» студентів: name + email
│   ├── topics.json     # теми з ключовими пунктами для оцінювання
│   └── personas.json   # рівні знань AI-студента
└── results/
    ├── exam_log.jsonl          # журнал подій start_exam / end_exam
    └── <email>_<час>.json      # повний результат кожного іспиту
```

### Формат результату

```json
{
  "email": "test@lpnu.ua",
  "name": "Test Student",
  "score": 7.5,
  "feedback": "Добре розуміє ... Варто попрацювати над ...",
  "topics": ["Промпт-інжиніринг", "Стратегії декодування тексту", "..."],
  "topic_results": {
    "Промпт-інжиніринг": { "score": 7.0, "comment": "..." }
  },
  "started_at": "2026-11-18T21:40:12",
  "finished_at": "2026-11-18T21:49:40",
  "history": [
    { "role": "system",    "content": "Вітаю! ...",            "datetime": "..." },
    { "role": "user",      "content": "Test Student, ...",     "datetime": "..." },
    { "role": "tool_call", "content": "{\"name\": \"start_exam\", ...}", "datetime": "..." }
  ]
}
```

У `history` роль `system` означає репліки екзаменатора, `user` означає відповіді студента, а `tool_call` містить виклики інструментів з аргументами й результатами.

## 🔧 Налаштування під себе

| Що змінити | Де |
|---|---|
| Список студентів | `data/students.json` |
| Теми та критерії оцінювання | `data/topics.json` (`title` + `key_points`) |
| Персони AI-студента | `data/personas.json` (`id`, `label`, `prompt`) |
| Кількість тем на іспит | `TOPICS_PER_EXAM` у `exam_tools.py` |
| Ліміт викликів інструментів за хід | `MAX_TOOL_STEPS` в `agent.py` |
| Стиль і правила екзаменатора | `SYSTEM_PROMPT` в `agent.py` |
| Провайдери й моделі за замовчуванням | `PROVIDERS` в `app.py` |

Стан кожного іспиту зберігається в окремому об'єкті `ExamSession` у `gr.State`, тому кілька студентів можуть складати іспит одночасно в різних вкладках браузера.
